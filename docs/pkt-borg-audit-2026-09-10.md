## Что остаётся описанием или решением мастера

Это не обещание полной автоматизации всех правил содержимого пакетов. Следующие свойства корректно представлены данными/описанием, но ещё не имеют самостоятельного обработчика события:

| Предмет / правило | Граница реализации |
|---|---|
| Стопа-Трансформер | Корректный модуль киберноги и стоимость. Превращение действием, штраф СКО −4 с минимумом 1 и исключение в невесомости не переключаются автоматически. |
| Устройство нулевой гравитации | По два слота в каждой из двух киберног; комплект Коперника проверен. Отдельное применение пары, горючее и снятие штрафов невесомости ведёт мастер. |
| Покрытие Сера | Тип, цена, ПЧ и ограничение ПКТ исправлены. Автоматического перехвата урона от огня нет. |
| Покрытие Хамелеон | Слоты, ПЧ и число установок учтены. Таймер неподвижности, обнаружение и снятие невидимости не автоматизированы. |
| АнтиЭМИ покрытие | Исправлена ошибочная подмена постоянным экранированием. Расход одного слоя при ЭМИ ещё не перехватывается. |
| Покрытие Бодивейт | Данные двух аппаратных слотов за установку сохранены. Передача аппаратных бонусов всем встроенным декам не реализована. |
| Бодискульптинг Близнецы | Без ПЧ; проверка совместимости по ТЕЛ. Распознавание внешности/ИК — описательное правило. |
| Устройство смены формы и условия среды | В системе нет общей модели невесомости; она не выводится из картинки или названия сцены. |
| Иммунитеты ПКТ | Штрафы проверки от состояния ранения убраны. Иммунитеты к отдельным критическим травмам, лекарствам, радиации и состояниям требуют решения мастера. |
| Отключение внутренней рамы по ЭМИ | Отдельное правило FAQ о сохранении ХП при временно отключённой раме не реализовано общим обработчиком ЭМИ. |
| Медицинская операция и смена тела | Четыре часа, проверка навыка, ремонт/терапия, питание Биосистемы и сюжетная необратимость операции не бросаются и не отсчитываются автоматически. |

Проверка точек интеграции в настоящей системе 0.92.4: `modules/api/actor/empable-items.js:getEMPableItems` только возвращает имена неэкранированных электронных предметов. Он не получает попадание, успешное воздействие ЭМИ, длительность отключения или расходуемый слой. Расход покрытия при чтении этого списка был бы ошибкой. `CPRActor._applyDamage` получает числовой дополнительный урон, но не идентификатор критической травмы; `CPRActorSheet._drawCriticalInjuryTable` независимо создаёт предмет травмы и затем обращается к `result[0]` для карточки. Простая отмена `preCreateItem` поэтому оставила бы урон и сломала карточку. В узкой обёртке списка целей иммунитет Биосистемы уже реализован без расходования предметов или изменения их флагов. Модель травмы содержит место, лечение и увеличение спасброска, но не машинный тип повреждённого органа. Полной автоматизации иммунитетов нужен отдельный согласованный поток определения травмы и урона; точечного безопасного события для всех путей применения в текущем core нет.
